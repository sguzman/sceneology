# Public repository and curated showcase

## Repository policy

A public engineering repository may contain successful, failed, inconclusive, shelved and experimental work, including neutral technical evaluations, diagnostics, tasks and incident reports. Public does not mean polished or approved. Keep failure cases reproducible when feasible.

Private *content*, not technical file categories, is excluded: private conversations or quotations, personal venting and autobiographical narratives, private identifiers and URLs, credentials, and media without publication rights. Sanitize the meaningful technical content rather than dropping entire categories solely by path.

The same privacy review applies to commit messages, test fixtures, comments, metadata, generated bundles, web resources and workflow logs.

## Website policy

The website is the owner's selected exhibition, not a mirror of everything in this repository.

1. Add a technical record to `catalog/library.json` when an implementation or experiment exists.
2. Keep its status accurate. Failure can remain in the library indefinitely.
3. An owner-selected record may be listed in `catalog/showcase.json`, but only with working public viewer and thumbnail paths, suitable rights and a real approval.
4. Removing an item from the showcase does not require deleting its source or technical history.
5. A private migration candidate is **never automatically** added to either catalog.

A passed test, attractive render or agent's judgment is not a substitute for the owner's artistic approval.
